# HMA UID Fake fork 0.3.13 TEST — Manual direct load

Исправлено поведение **Manual inject** из 0.3.12: ручной выбор теперь действительно пропускает собственную предварительную проверку KMI/ABI UIDFAKE, а не повторяет автоматический выбор.

- После выбора одного из восьми комплектных `.ko` и отдельного подтверждения риска выбранный файл передаётся непосредственно `finit_module(flags=0)`. Проверки идентичности KMI, ELF/CRC в userspace и профиль несовпадений не блокируют эту ручную попытку.
- **Это не гарантия успешной загрузки.** Само ядро проверяет модуль и может отказать из-за vermagic, CRC, подписи, символов или своей политики. Не применяются force flags, исправление CRC/vermagic, отключение защиты ядра и запасные загрузчики. Реальный результат/errno показывается пользователю, журнал сохраняется в диагностике.
- Ручная попытка может привести к зависанию, перезагрузке и потере несохранённых данных, особенно если кастомное ядро само игнорирует несовпадения CRC. Для Kitsune-SpiritFox #20 остаются известными 15 несовпадений ABI. Пользователь должен понимать риск; эта сборка не заявляет совместимость с ним.
- Автоматическая загрузка сохраняет все проверки. Ручная попытка одноразовая, не превращается в автоматическую загрузку неподтверждённого кандидата на следующих перезагрузках. Правила HMA/HMA-OSS не меняются.
- Пункт доступен при отсутствии ядрового endpoint. Сохранены защита от двойной загрузки, единственный процесс синхронизации, выбор источника правил и кнопка диагностики.

Установка: ZIP поверх тестовой версии → перезагрузка → при неудачной автоматической загрузке WebUI → **Manual inject** → нужный KMI → **Принимаю риск — загрузить**. Перед экспериментом сохраните данные и подготовьте способ отключения проблемного модуля через recovery/ADB. После попытки сохраните диагностику.

Версия `0.3.13-test-fork`, versionCode `3013`. Prerelease; стабильный Latest не заменяется. CI проверяет поведение ручного пути с заглушкой системного вызова, не загружает модуль в ядро и не доказывает работу на телефоне.
