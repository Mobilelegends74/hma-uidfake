# HMA UID Fake fork 0.3.11 TEST

Следующий prerelease после 0.3.8 TEST с кнопкой диагностики. Stable / Latest остаётся 0.3.7-fork.

## Источники правил

- На главном экране добавлен переключатель **HMA / HMA-OSS ↔ Ручной**. По умолчанию используется HMA-OSS; старый HMA поддерживается как внешний источник при отсутствии OSS.
- Существующие ручные конфиги сохраняются, но больше не перекрывают HMA-OSS автоматически. Редактирование, импорт или удаление ручных правил не меняет выбранный режим.
- Переключение сохраняется отдельно от правил и применяется без перезагрузки. Если выбранный конфиг исчез, старые UID-правила очищаются, а не остаются в ядре. Устаревшая копия `modules/hma-uidfake/config.json` больше не подхватывается.
- Исправлен пересчёт UID-политики при установке/удалении приложений, а не только обновление списка APK; отдельно отслеживается изменение/атомарная замена packages.xml, чтобы учитывать окончательно записанные UID. Исправлена первая отправка пустой политики после изменения источника.
- При загруженном модуле и нуле правил WebUI отдельно поясняет, что нужно проверить источник. Обновлена справка RU/EN; кнопка диагностики сохранена и теперь включает выбранный режим и live kernel build-ID notes.

## Кастомное ядро 5.10 — важное ограничение

- Обнаруживается ситуация, когда ядро игнорирует ошибки CRC (`disagrees about version … but ignore`). CRC загруженных vendor-модулей в таком случае больше не считаются доказательством ABI ядра.
- Для предоставленного образа **Kitsune-SpiritFox 5.10.269 #20** добавлен профиль CRC, извлечённых из самого ARM64 Image, с проверкой полного banner и live GNU build ID. Сравниваются все импорты кандидата, без переписывания CRC, vermagic и без force-load. Добавлена повторная проверка непосредственно перед загрузкой.
- **Это не готовая поддержка загрузки на данном Kitsune.** Существующий android12-5.10 `.ko` отличается от ABI образа; проверенные предоставленные исходники веток 16.0/16.2 также не дали совпадающих сигнатур. В этом случае тестовая версия объясняет точную причину отказа (`ABI_KERNEL_MISMATCH` / `PROFILE_ID_UNVERIFIED`), но не пытается загрузить неподтверждённый модуль. Нужны исходники/подготовленный build tree именно установленного образа и согласованная сборка `.ko`.
- Инструмент `scripts/kernel-image-abi.py` предназначен для read-only анализа определённого ARM64 Image layout; неподдерживаемые форматы отвергаются. Пользовательские журналы/бинарные образы в репозиторий не включены.

## Установка и тест

Установите `hma-uidfake-fork-0.3.11-test.zip` поверх текущей версии и перезагрузитесь. По умолчанию выберется HMA/HMA-OSS. Для собственных правил явно выберите **Ручной**; старые ручные настройки не удаляются. Проверьте смену источника и удаление правил, затем сохраните диагностику нижней кнопкой.

Версия `0.3.11-test-fork`, versionCode `3011`. Восемь исходных KMI сохранены. CI не подтверждает работу всех хуков на устройстве. Архив диагностики содержит названия приложений и правила; передавайте его лично.
